# AGENTS.md

Guidance for coding agents working in this repository.

## What this project is

A print-ready book: the complete annotated source code of **Bitcoin v0.1.0**
(Satoshi Nakamoto, January 2009). Chapters are generated from YAML annotation
files; primers, front/back matter, and colophon are hardcoded HTML in
`scripts/build.js`. The cover is generated by `scripts/build-cover.js`.

## Commands

| Command | Purpose |
|---|---|
| `npm install` | Install dependencies (Node.js 18+) |
| `npm run fetch` | Copy the committed v0.1.0 archive into `src/bitcoin-0.01/` (gitignored) and verify it against `src/source-manifest.json` |
| `npm run verify:source` | Re-hash `src/bitcoin-0.01/src` against the manifest (`--write` regenerates it) |
| `npm run fetch:versions` | Download all book-referenced Bitcoin Core source trees into `src/versions/` (gitignored; ~750 MB) |
| `npm run validate` | Verify source hashes, then validate all annotations (YAML schema, citation keys, line anchors, glossary shape) and `src/reading-paths.yaml` steps. **Runs automatically before `npm run build`.** |
| `npm run check:quotes` | Check every quoted Satoshi passage against the Nakamoto Institute corpus in `src/nakamotoinstitute.org/` (skips if absent; runs in `npm run release`) |
| `node scripts/symbols.mjs --report [Name…]` | Inspect the definition/caller table behind the book's "Called from" cross-references |
| `npm run build` | Build `output/bitcoin-alpha-book.html` |
| `npm run preview` | Local preview server (also syncs edition strings into stale HTML) |
| `npm run open` | Same as `preview` but also opens the site in the default browser (`scripts/preview.js --open[=path]`) |
| `npm run pdf` | Render the book PDF (Paged.js + Puppeteer; also writes `output/book-meta.json`) |
| `npm run cover` / `npm run cover:pdf` | Cover HTML / cover PDF (reads `book-meta.json` for spine width) |
| `npm run thumbnails` | Thumbnail grid + contact sheet PNGs |
| `npm test` | Index-generation tests (`scripts/test-index.js`) — the only test suite |
| `npm run release` | Full pipeline, copies deliverables to `releases/YYYY-MM-DD_HH-MM-SS/` |
| `node scripts/content-review.mjs` | Continuous-scroll proofing manuscript server |
| `npm run build:web` | Assemble the static site into `dist/` (book + cover + landing page; run after `build`/`cover`) |
| `npm run build:netlify` | Full Netlify pipeline: fetch → build → cover → build:web |

## Netlify

`netlify.toml` deploys the book as a static site: build command
`npm run build:netlify`, publish dir `dist/` (gitignored, assembled by
`scripts/build-web.js`: `index.html` landing, `book.html`, `cover.html`,
`contact-sheet.png`, `_redirects` for `/book` and `/cover`). Only `dist/` is
deployed — research material in `src/` (filenames with spaces/`?`, which
Netlify rejects) never leaves the repo. No Chromium on Netlify: PDF/thumbnail
steps are local-only. The cover's donation QR comes from the committed
`output/donation-cover.json`, so no env vars are needed.

## Hard rules for content edits

1. **Run `npm run validate` after touching `src/annotations/`.** The build
   silently drops annotations it cannot place (missing `type:` etc.) — the
   validator exists because ten `uiproject.fbp` annotations were once lost
   to exactly that. Validation failures stop the build.
2. **Annotations (`src/annotations/*.yaml`)**: schema in `_template.yaml`.
   Types: `margin` (needs `line` + `text`), `block` (needs `lines` + `text`),
   `highlight` (needs `lines` + `category`). Optional per-chapter
   `sources:` (local citation keys) and `glossary:` (renders as "Key Terms"
   after the chapter summary).
3. **Citations**: use `{{cite:key}}` after factual claims; keys live in
   `src/references.yaml` (or chapter-local `sources:`). Verify claims before
   adding them — the book's factual bar is "checked against the v0.1.0 source
   and primary documents". Quotes must match primary sources verbatim.
4. **Voice**: American English, em-dashes as found, plain-HTML prose
   (`<p>`, `<code>`, `<em>`, `<strong>`). Preserve the author's style; fix
   errors, don't rewrite for taste.
5. **Quotes**: `npm run check:quotes` must report no `NOT FOUND`. A quoted
   phrase that is not a quotation (an example, a term) goes in `NOT_QUOTES`
   in `scripts/check-quotes.mjs` with its reason.
6. **Reading paths** (`src/reading-paths.yaml`): steps name a definition by
   its qualified name (`symbol: "CBlock::AcceptBlock"`) or a `file:` +
   `line:`; the build prints the page number. Notes are checked against the
   source like any annotation.
7. **Book prose** (Introduction, primers, What Came After, colophon) lives in
   `scripts/build.js`; back-cover copy lives in `scripts/build-cover.js`.
   Line-count claims use wc-style totals (the v0.1.0 tree is 19,820 lines of
   C++ — "roughly 20,000").
8. **Edition bumping**: change `EDITION` (and `ANNOTATIONS_CREDIT` when the
   author/reviser set changes) in `scripts/edition.mjs` — it propagates to
   title page, colophon, cover, spine, and preview chrome. Then rebuild
   (`npm run build && npm run cover`). Tag shipped releases in git.
9. **GitHub release assets are edition-stamped**: book PDF uploads as
   `bitcoin-alpha-book-<EDITION>.pdf`, cover as `bitcoin-alpha-cover-<EDITION>.pdf`
   (e.g. `bitcoin-alpha-book-v0.3.5.pdf`). Rename via
   `gh api -X PATCH repos/.../releases/assets/<id> -f name=...` if an asset
   was uploaded unversioned.

## Repository policies

- **Canonical source**: `src/bitcoin-0.1.0 January 3, 2009 Alpha Nakamoto Institute/`
  is the committed v0.1.0 release; `src/source-manifest.json` holds its
  SHA-256 per file and tree hash (printed in the colophon). Do not use
  `trottier/original-bitcoin` master — it is v0.1.3, and line anchors drift.
  `.gitattributes` keeps the archive's CRLF bytes intact.
- **Gitignored source trees**: `src/bitcoin-0.01/` (`npm run fetch`),
  `src/versions/` (`npm run fetch:versions`), `src/nakamotoinstitute.org/`,
  `src/programmingbitcoin/` (research clones). These are regenerable or
  re-clonable; do not commit them. Note: a local `src/bitcoin-0.01/` may be a
  git clone — `npm run fetch` never deletes its `.git`; it only replaces `src/`
  when that fails verification.
- **Build artifacts**: `output/*.html` and `output/*.pdf` are gitignored;
  `output/*.png`, `output/*.json` and `releases/*/` ARE committed (release
  history is part of the repo).
- **Never commit secrets.** Donation config lives in the gitignored `.env`
  (see `.env.example`): `BITCOIN_SILENT_PAYMENT_ADDRESS` (BIP 352, wins when
  set) and `BITCOIN_DONATION_XPUB` (BIP84 account xpub, per-release address
  rotation). The build falls back to a clearly-invalid placeholder QR when
  neither is set. The derived payload in `output/donation-cover.json` is
  public-by-design (it is printed on the cover) and committed. No key
  material of any kind belongs in tracked files.

## Validation & CI

- `npm run validate` — source hashes, annotation schema/citations/line
  anchors, reading-path steps (blocking); missing glossaries are warnings.
- `npm run check:quotes` — Satoshi quotes vs. primary sources (local only;
  needs the Nakamoto Institute clone; run by `npm run release`).
- `npm run release` writes `SHA256SUMS` into each `releases/<stamp>/`
  folder; `npm run build:web` publishes the latest one plus
  `source-manifest.json`.
- `npm test` — index tests.
- `.github/workflows/ci.yml` runs fetch → validate → test → build on
  push/PR.
