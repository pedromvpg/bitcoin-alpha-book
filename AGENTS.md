# AGENTS.md

Guidance for coding agents working in this repository.

## What this project is

A print-ready book: the complete annotated source code of **Bitcoin v0.01 Alpha**
(Satoshi Nakamoto, January 2009). Chapters are generated from YAML annotation
files; primers, front/back matter, and colophon are hardcoded HTML in
`scripts/build.js`. The cover is generated by `scripts/build-cover.js`.

## Commands

| Command | Purpose |
|---|---|
| `npm install` | Install dependencies (Node.js 18+) |
| `npm run fetch` | Download the v0.01 source into `src/bitcoin-0.01/` (gitignored) |
| `npm run fetch:versions` | Download all book-referenced Bitcoin Core source trees into `src/versions/` (gitignored; ~750 MB) |
| `npm run validate` | Validate all annotations: YAML schema, citation keys, line anchors. **Runs automatically before `npm run build`.** |
| `npm run build` | Build `output/bitcoin-alpha-book.html` |
| `npm run preview` | Local preview server (also syncs edition strings into stale HTML) |
| `npm run pdf` | Render the book PDF (Paged.js + Puppeteer; also writes `output/book-meta.json`) |
| `npm run cover` / `npm run cover:pdf` | Cover HTML / cover PDF (reads `book-meta.json` for spine width) |
| `npm run thumbnails` | Thumbnail grid + contact sheet PNGs |
| `npm test` | Index-generation tests (`scripts/test-index.js`) — the only test suite |
| `npm run release` | Full pipeline, copies deliverables to `releases/YYYY-MM-DD_HH-MM-SS/` |
| `node scripts/content-review.mjs` | Continuous-scroll proofing manuscript server |

## Hard rules for content edits

1. **Run `npm run validate` after touching `src/annotations/`.** The build
   silently drops annotations it cannot place (missing `type:` etc.) — the
   validator exists because ten `uiproject.fbp` annotations were once lost
   to exactly that. Validation failures stop the build.
2. **Annotations (`src/annotations/*.yaml`)**: schema in `_template.yaml`.
   Types: `margin` (needs `line` + `text`), `block` (needs `lines` + `text`),
   `highlight` (needs `lines` + `category`). Optional per-chapter
   `sources:` (local citation keys) and `glossary:` (renders as "Key Terms"
   after the chapter summary).
3. **Citations**: use `{{cite:key}}` after factual claims; keys live in
   `src/references.yaml` (or chapter-local `sources:`). Verify claims before
   adding them — the book's factual bar is "checked against the v0.01 source
   and primary documents". Quotes must match primary sources verbatim.
4. **Voice**: American English, em-dashes as found, plain-HTML prose
   (`<p>`, `<code>`, `<em>`, `<strong>`). Preserve the author's style; fix
   errors, don't rewrite for taste.
5. **Book prose** (Introduction, primers, What Came After, colophon) lives in
   `scripts/build.js`; back-cover copy lives in `scripts/build-cover.js`.
   Line-count claims use wc-style totals (the v0.01 tree is 19,820 lines of
   C++ — "roughly 20,000").
6. **Edition bumping**: change `EDITION` (and `ANNOTATIONS_CREDIT` when the
   author/reviser set changes) in `scripts/edition.mjs` — it propagates to
   title page, colophon, cover, spine, and preview chrome. Then rebuild
   (`npm run build && npm run cover`). Tag shipped releases in git.
7. **GitHub release assets are edition-stamped**: book PDF uploads as
   `bitcoin-alpha-book-<EDITION>.pdf`, cover as `bitcoin-alpha-cover-<EDITION>.pdf`
   (e.g. `bitcoin-alpha-book-v0.3.5.pdf`). Rename via
   `gh api -X PATCH repos/.../releases/assets/<id> -f name=...` if an asset
   was uploaded unversioned.

## Repository policies

- **Gitignored source trees**: `src/bitcoin-0.01/` (`npm run fetch`),
  `src/versions/` (`npm run fetch:versions`), `src/nakamotoinstitute.org/`,
  `src/programmingbitcoin/` (research clones). These are regenerable or
  re-clonable; do not commit them. Note: `src/bitcoin-0.01/` is itself a git
  clone of `trottier/original-bitcoin` — leave its `.git` alone.
- **Build artifacts**: `output/*.html` and `output/*.pdf` are gitignored;
  `output/*.png`, `output/*.json` and `releases/*/` ARE committed (release
  history is part of the repo).
- **Never commit secrets.** Donation config lives in the gitignored `.env`
  (see `.env.example`): `BITCOIN_SILENT_PAYMENT_ADDRESS` (BIP 352, wins when
  set) and `BITCOIN_DONATION_XPUB` (BIP84 account xpub, per-release address
  rotation). The build falls back to a clearly-invalid placeholder QR when
  neither is set. The derived payload in `output/donation-cover.json` is
  public-by-design (it is printed on the cover) and committed. No key
  material of any kind belongs in tracked files.

## Validation & CI

- `npm run validate` — annotation schema/citations/line anchors (blocking).
- `npm test` — index tests.
- `.github/workflows/ci.yml` runs fetch → validate → test → build on
  push/PR.
